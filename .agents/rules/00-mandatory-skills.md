# Regla: Lectura Obligatoria de Skills

Antes de analizar, responder, planificar, editar código o ejecutar comandos para cada nueva solicitud del usuario, debes acatar las siguientes instrucciones de contexto inquebrantables.

## Instrucciones

1. **Lectura Base:** Debes leer completamente y hasta EOF la skill `centros-integrales-domain` y su `DOMAIN_MODEL.md` asociado. Debes leer también la skill de diseño instalada.
2. **Frontend:** Si la tarea afecta React, frontend o componentes visuales, lee obligatoriamente `react-best-practices`.
3. **Backend/DB:** Si la tarea afecta Supabase, Auth, SQL, migraciones o RLS, lee obligatoriamente `supabase` y `supabase-postgres-best-practices`.
4. **Exclusión Estricta:** NO cargues ni leas la skill `sri-electronic-billing` cuando la tarea no afecte la facturación electrónica.
5. **Ciclo de Verificación:** Debes repetir esta comprobación al recibir una nueva solicitud, al cambiar de tarea, al reanudar una sesión y al perder o compactar contexto (por ejemplo, después de un checkpoint).
6. **Reporte Riguroso:** Antes de comenzar a trabajar, INFORMA las rutas exactas y absolutas que has leído. No basta con decir "Viewed SKILL.md". 
7. **Lectura Completa:** No afirmes que un archivo fue leído completamente si solo inspeccionaste un intervalo parcial (líneas X a Y sin llegar al final).
8. **Manejo de Bloqueos:** Si falta una skill obligatoria o no puede leerse, DETENTE inmediatamente y reporta el bloqueo al usuario.
9. **Respeto a la Arquitectura:** Trata este archivo, `AGENTS.md`, el modelo de dominio y las decisiones arquitectónicas previamente aprobadas como normas vinculantes e irrevocables.
10. **Aprobación para Cambios Mayores:** No alteres ninguna decisión arquitectónica, de dominio o estructura base existente sin explicar primero el conflicto al usuario y solicitar explícitamente su aprobación.
